1. Incident information

```text
GEMINI_API_KEY
```

* logs
* API responses
* frontend
* exceptions
* test output
* source code

---

# AI COST LIMIT

This project is being developed using the **Gemini API Free Tier**.

Therefore, minimize API usage.

IMPORTANT:

Do NOT call Gemini:

* once for every log
* once for every metric
* once for every RAG chunk
* repeatedly for the same incident
* during document indexing
* during deterministic calculations

Instead:

```text
Many logs
   ↓
Python aggregation
   ↓
Structured evidence
   ↓
RAG top-K evidence
   ↓
ONE Gemini reasoning request
```

Use deterministic Python for preprocessing.

Gemini should only perform the reasoning that actually requires an LLM.

---

# DO NOT USE GEMINI FOR

Do not use Gemini to calculate:

* error rate
* request count
* latency
* p95
* p99
* timestamps
* metric differences
* deployment timestamps
* threshold comparisons
* similarity scores
* database values

Python should calculate these deterministically.

Gemini receives the calculated results.

# GEMINI PROMPT DESIGN

Create a dedicated system/instruction prompt for Gemini.

Gemini must be instructed:

You are an SRE incident-analysis assistant.

Analyze only the evidence provided.

Do not invent facts.

Do not assume that correlation proves causation.

Do not claim certainty when evidence is incomplete.

Generate multiple plausible hypotheses when appropriate.

For every hypothesis, identify supporting and contradicting evidence.

Prefer evidence from:

1. Direct incident telemetry
2. Logs
3. Metrics
4. Deployment records
5. Retrieved operational knowledge
6. Historical incidents

Historical incidents are supporting context only and must not automatically be treated as the current incident's cause.

Return structured JSON only.

# REQUIRED GEMINI OUTPUT

Gemini must return structured JSON.

Use a schema similar to:

```json
{
  "incident_id": "INC-SIM-001",
  "summary": "string",
  "hypotheses": [
    {
      "hypothesis_id": "H1",
      "statement": "string",
      "supporting_evidence": [
        {
          "evidence_id": "E1",
          "reason": "string"
        }
      ],
      "contradicting_evidence": [],
      "confidence": 0.0
    }
  ],
  "primary_hypothesis": {
    "hypothesis_id": "H1",
    "reason": "string"
  },
  "evidence_chain": [
    "E1",
    "E2",
    "E3"
  ],
  "uncertainties": [],
  "recommended_next_checks": []
}
```

Confidence must be represented as a number between:

```text
0.0 and 1.0
```

Do NOT convert confidence into a political-style score or ranking.

It is simply an uncertainty indicator for the technical diagnosis.

# EVIDENCE IDs

Before sending the request to Gemini, assign deterministic IDs.

Example:

```text
E1 → database timeout log
E2 → 75% error rate
E3 → increased p95 latency
E4 → deployment #1842
E5 → database pool changed from 50 to 10
E6 → checkout timeout runbook
E7 → historical incident INC-873
```

Gemini must reference these IDs.

This creates an explicit evidence chain.

---

# IMPORTANT ANTI-HALLUCINATION RULE

Gemini must not introduce evidence that does not exist in the supplied incident context.

For example, Gemini must NOT say:

```text
CPU reached 95%
```

unless CPU evidence was actually supplied.

Gemini must NOT say:

```text
Database server crashed
```

unless evidence explicitly supports it.

If evidence is missing, Gemini should say:

```text
insufficient evidence
```

or include the issue under:

```text
uncertainties
```

# RESPONSE VALIDATION

Never blindly trust the Gemini response.

Validate:

1. Response exists.
2. JSON can be parsed.
3. Required fields exist.
4. Confidence is between 0 and 1.
5. Evidence IDs referenced by Gemini actually exist.
6. Hypothesis IDs are valid.
7. No unknown evidence IDs are accepted.
8. Strings have reasonable length.
9. Arrays do not exceed configured limits.

If validation fails, return a controlled error.

Do not silently convert invalid AI output into a valid diagnosis.
